# NotebookLM browser adapter

The CLI packages sources and verifies recorded receipts; the active agent performs the live browser work using its documented computer/browser tools. UI wording, quotas and supported URLs change. Inspect the current product and official documentation. The human-facing product may say NotebookLM or Gemini Notebook; do not infer account access from a brand label.

1. Use the existing **Pulse Vibe Daily** Google browser account. Verify the visible account/profile before uploading; do not export cookies or switch an unrelated active account. If the intended session is absent, ask for that missing login rather than operating in another account.
2. Look up the account + `collection_key` in the workspace notebook registry. Reopen its exact observed URL. The **playlist title** is the notebook title; date/batch IDs belong in local run metadata. If no registry entry exists, check for a matching existing notebook before creating one. Resolve ambiguous same-title notebooks explicitly. Preserve the observed notebook ID across later runs.
3. Inspect current source allowance/usage. Run `package RUN --source-cap CURRENT_CAP --words-per-source 40000`. The default cap of 50 is conservative configuration, not an entitlement claim. One slot is reserved. Only active files listed in `package.json` are intended uploads. Flat text packets include all cleaned captions and rich analysis; HTML dropdown structure is not trusted as an ingestion format.
4. Compare current packet hashes with earlier source receipts. Reuse unchanged sources. Stage changed revisions and verify them before retiring managed older versions; preserve unrelated user sources. Do not delete sources or create a duplicate notebook to bypass quota. If packed substance exceeds capacity, return a named-volume plan; do not drop videos or shrink the corpus into a thin summary.
5. Upload/insert sources using the supported UI, wait for ready state, verify every expected source identity/title, and inspect representative contents. Ask source-specific questions drawn from early, middle and late portions, checking citations against local evidence. Save source receipts and dated browser observations. A local file size/word ratio is not ingestion proof.
6. Generate the requested **Audio Overview and Slide Deck** with prompts tied to the user's goal. Persist observed generation IDs/status immediately. Resume a pending artifact rather than clicking Generate again. Respect actual quota responses; record `waiting_quota` and the visible reset guidance without busy polling or promising a fabricated reset time.
7. Open the completed audio and deck. Verify source-specific content and inspect representative slides. Record the source-package revision each used; changed sources invalidate previous generation claims. Download deliverables when requested/supported and retain originals. A “ready” UI state and content review are separate observations.
8. Save `notebooklm/state.json`, then `register-notebook RUN --registry PATH` and `verify RUN`. Registration rejects a conflicting existing mapping. It does not prove generation completed. Keep notebooks under their existing private access policy; public sharing is a separate action.

If an artifact is still generating when the active session ends, give its exact notebook/artifact location and the next check. Do not install a recurring automation without a scheduling request. Optional mind maps or data tables can be generated later in the same notebook; they are not required for this user's core audio-plus-slides experience.
