# NotebookLM browser adapter

The CLI packages sources and verifies recorded receipts; the active agent performs the live browser work using its documented computer/browser tools. UI wording, quotas and supported URLs change. Inspect the current product and official documentation. The human-facing product may say NotebookLM or Gemini Notebook; do not infer account access from a brand label.

1. Use the Google browser account named by `notebook_account_label` in the workspace `settings.json` (for this owner, **Pulse Vibe Daily**); new runs record it at `init`, and packaging refuses a run with none. Verify the visible account/profile before uploading; do not export cookies or switch an unrelated active account. If the intended session is absent, ask for that missing login rather than operating in another account.
2. Look up the account + `collection_key` in the workspace notebook registry. Reopen its exact observed URL. The **playlist title** is the notebook title; date/batch IDs belong in local run metadata. If no registry entry exists, check for a matching existing notebook before creating one. Resolve ambiguous same-title notebooks explicitly. Preserve the observed notebook ID across later runs.
3. Inspect current source allowance/usage. Run `package RUN --source-cap CURRENT_CAP --words-per-source 40000`. The default cap of 50 is conservative configuration, not an entitlement claim. One slot is reserved by this local policy. New full runs package exactly one complete enriched source per unique video, with the video title and ID. Only active files listed in `package.json` are intended uploads. For new full runs, flat text sources contain the neutral expanded timed account and reviewed visual observations. `--caption-mode retained` additionally embeds original captions; references mode keeps them locally. Historical runs retain their recorded packaging behavior. HTML dropdown structure is not trusted as an ingestion format.
4. Compare current packet hashes with earlier source receipts. Reuse unchanged sources. Stage changed revisions and verify them before retiring managed older versions; preserve unrelated user sources. Do not delete sources or create a duplicate notebook to bypass quota. If one video exceeds a configured word/file budget, verify the actual provider limit and return an explicit exception plan. If the collection exceeds source capacity, return a named-volume plan with one source per video in each volume. Never split one video or blend videos automatically.
5. Upload/insert sources using the supported UI, wait for ready state, verify exactly one distinct ready source identity/title per video, and inspect representative contents. Ask source-specific questions drawn from early, middle and late portions, checking citations against local evidence. Save source receipts and dated browser observations. A local file size/word ratio is not ingestion proof.
6. Generate the requested **Audio Overview and Slide Deck** with prompts that explain the collection's own subject faithfully. A project-oriented Studio output requires an explicit project request; its prompt must distinguish application from source claims. Persist observed generation IDs/status immediately. Resume a pending artifact rather than clicking Generate again. Respect actual quota responses; record `waiting_quota` and the visible reset guidance without busy polling or promising a fabricated reset time.
7. Open the completed audio and deck. Verify source-specific content and inspect representative slides. Record the source-package revision each used; changed sources invalidate previous generation claims. Download deliverables when requested/supported and retain originals. A “ready” UI state and content review are separate observations.
8. Save `notebooklm/state.json`, then `register-notebook RUN --registry PATH` and `verify RUN`. Registration rejects a conflicting existing mapping. It does not prove generation completed. Keep notebooks under their existing private access policy; public sharing is a separate action.

If an artifact is still generating when the active session ends, give its exact notebook/artifact location and the next check. Do not install a recurring automation without a scheduling request. Optional mind maps or data tables can be generated later in the same notebook; they are not required for this user's core audio-plus-slides experience.
